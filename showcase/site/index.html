PlayForge

输入一句话，得到一个真的能玩的小游戏。

Claude 写代码 · Codex 审查 · AI 在浏览器里真的去玩，发现问题自动修复。下面每个游戏都是这样生成的，可以直接玩，也可以展开看它的生成过程。

工作流程

  1. 一句话需求例如"躲陨石的太空飞船游戏"
  2. Claude 写代码在 Docker 沙箱里基于带探针的 Vite 模板实现
  3. Codex 审查阻塞问题打回修复，最多 3 轮
  4. AI 试玩Playwright 读探针、按键、截图，检查能否真的玩
  5. 自动修复试玩失败的原因交给 Claude，最多 2 次
  6. 提交 & 预览每轮一个 git 提交，通过后可在线玩

生成的游戏

点"开始玩"后先点一下游戏画面，再用键盘操作（方向键 / 空格）。

技术要点

可恢复的多 Agent 编排

Java 21 + Spring Boot。纯函数状态机决定下一步，每一步落库；崩溃或重启后从断点续跑，不重复提交。审查分阻塞/建议两级，最终以试玩结果为准。

AI 试玩（探针协议）

生成的游戏必须暴露 window.__GAME_PROBE__。Playwright 在无输入对照下按键采样，判断操作是否真的生效；画面空白、报错、卡死、资源路径错误都能识别。

Docker 预热沙箱

CLI 在容器内运行，用完即毁；代码以 tar 流同步，拒绝 ..、.git 变体与符号链接。强停后的残留容器下次启动自动清理。

安全

凭证只以环境变量名传入容器，事件流统一脱敏；预览运行在 CSP 沙箱（不透明源），生成的代码无法调用平台 API；AI 文本一律按纯文本渲染。

实时与可追溯

SSE 推送全过程，支持 Last-Event-ID 断线续传；同一份事件日志也是这里"生成过程"的数据来源。

测试

后端 190+ 测试（含真实 Docker 集成测试）、前端 30+ 测试，以及 14 个"有问题的游戏"样本专门验证试玩不会误判。
