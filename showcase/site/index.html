它是怎么做到的

每个游戏都经过同一条流水线。和"编译通过就算成功"不同，这里以 AI 真的去玩为准。

  1. 1一句话需求"躲陨石的太空飞船游戏"
  2. 2Claude 写代码Docker 沙箱里基于带探针的 Vite 模板实现
  3. 3Codex 审查阻塞问题打回修复，最多 3 轮
  4. 4AI 试玩Playwright 读探针、按键、截图
  5. 5自动修复把试玩失败原因交给 Claude
  6. 6提交 & 上线git 提交，通过即可在线玩

技术要点

🧭

可恢复的多 Agent 编排

纯函数状态机决定下一步，每一步落库；崩溃或重启后从断点续跑，不重复提交。审查意见冲突时以试玩结果为准。

🎮

AI 试玩（探针协议）

游戏必须暴露 window.__GAME_PROBE__。先观察无输入对照，再按键并持续采样，判断操作是否真的生效。

📦

Docker 预热沙箱

CLI 在容器内运行、用完即毁；tar 同步拒绝 ..、.git 变体与符号链接；强停残留自动清理。

🔒

安全

凭证只传变量名、事件统一脱敏；预览运行在 CSP 沙箱中，生成的代码碰不到平台 API；AI 文本只按纯文本渲染。

📡

实时可追溯

SSE 推送全过程并支持断线续传；同一份事件日志就是这里"生成过程"的数据来源。

🧪

测试

后端 190+（含真实 Docker 集成测试）、前端 30+，另有 14 个"有问题的游戏"样本专门防止试玩误判。
